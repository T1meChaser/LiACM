## Overview

LiACM Pro is a learned LiDAR point-cloud geometry codec built on a coarse-to-fine
sparse occupancy coding backbone. It combines LiDAR-aware context construction
with causality-constrained context utilization, a streamlined parent branch,
cross-layer feature reuse, and physically aligned hierarchy conditioning.

This release provides encoding, decoding, evaluation, and pretrained models.
Training scripts, training records, and datasets are not included.

## Installation

The released models were evaluated on Linux with an NVIDIA GPU using Python
3.8.20, PyTorch 2.0.0, CUDA 11.8, TorchSparse 2.1.0, and torchac 0.9.3.

```bash
conda create -n liacm_pro python=3.8.20 -y
conda activate liacm_pro

sudo apt-get update
sudo apt-get install -y build-essential curl

pip install torch==2.0.0 torchvision==0.15.1 torchaudio==2.0.1 \
    --index-url https://download.pytorch.org/whl/cu118

python -c "$(curl -fsSL https://raw.githubusercontent.com/mit-han-lab/torchsparse/385f5ce8718fcae93540511b7f5832f4e71fd835/install.py)"
pip install -r requirements.txt

chmod +x utils/third_party/pc_error_d
sha256sum -c SHA256SUMS
```

Run these commands from the project root. A working C++ compiler is required:
torchac builds its extension on first use. The bundled `pc_error_d` is Linux
x86-64 version 0.13.4. Native Windows and CPU-only codec execution are not supported.
Do not enable `expandable_segments` with the documented PyTorch 2.0 environment.

## Pretrained Models

| Dataset | Checkpoint | Parameters | Base step |
|---|---|---:|---:|
| SemanticKITTI | `LiACM_Pro_SemanticKITTI.pt` | 2,546,320 | 4 mm |
| Ford | `LiACM_Pro_FORD.pt` | 2,546,320 | 4 mm |

Both files are included in the project root and contain model tensors only,
without epochs, optimizer states, or other training metadata. The standard
scripts load them directly; no conversion or original training checkpoint is
required. Omitting `--ckpt` selects the dataset-specific file automatically.

Only load checkpoint files obtained from a trusted source. The loader verifies
the published file hash, supplies the fixed architecture from `utils/pretrained.py`,
and loads tensors strictly using `weights_only=True`. Do not re-save or edit the
published files. Legacy LiACM checkpoints are not interchangeable with Pro weights.
Encoding and decoding must use the same model and settings.

## Data Preparation

The datasets are not redistributed. Please obtain them from their official
sources and follow their respective licenses.

**SemanticKITTI:** original Velodyne scans are read from `*.bin` files under
`sequences/<id>/velodyne/` (XYZ in meters, plus reflectance). Evaluation requires
matching reference PLY files in meters, such as `predata/11/000000.ply`, generated
from the same raw points without filtering, rounding, or changing frame IDs.
Reference PLYs are not generated by this package.

**Ford:** the codec reads 1-mm pre-quantized PLY point clouds. The test layout is
`Ford/Ford_02_q_1mm/Ford_02_q_1mm/*.ply` and
`Ford/Ford_03_q_1mm/Ford_03_q_1mm/*.ply`. Do not convert these coordinates to meters.

The commands below use the bundled metric's normal handling (`--input_norm none`).
If using external reference normals, select the appropriate normal options
consistently across methods; changing the normal source can change D2-PSNR.

## Reproducing the Main Results

One checkpoint is reused across six coordinate-precision operating points for
each dataset. Both models use a fixed 4-mm base lattice. Offsets `0,1,2,3,4,5`
give effective steps `4,8,16,32,64,128` mm. Lower-rate reconstructions use prefixes
of that hierarchy; do not change `q_base` or independently re-quantize the input.
These offsets are not universal bit-depth or posQ labels for other codecs.

### Ford

```bash
CUDA_VISIBLE_DEVICES=0 python run_rd_pipeline.py \
    --dataset_mode FORD \
    --dataset_split test \
    --ford_root='/path/to/Ford' \
    --ford_test_seqs='Ford_02_q_1mm,Ford_03_q_1mm' \
    --ckpt='./LiACM_Pro_FORD.pt' \
    --depth_offsets='0,1,2,3,4,5' \
    --resolution=30000 --input_norm=none \
    --enable_cd --cd_mode=gaem
```

### SemanticKITTI

```bash
CUDA_VISIBLE_DEVICES=0 python run_rd_pipeline.py \
    --dataset_mode SKITTI \
    --dataset_split test \
    --skitti_root='/path/to/SemanticKITTI/data_odometry_velodyne/dataset/sequences' \
    --skitti_predata_root='/path/to/SemanticKITTI/predata' \
    --ckpt='./LiACM_Pro_SemanticKITTI.pt' \
    --depth_offsets='0,1,2,3,4,5' \
    --resolution=59.7 --input_norm=none \
    --enable_cd --cd_mode=gaem
```

The pipeline writes bitstreams, reconstructed PLYs, and per-frame CSV results
under `./my_test/`, and prints dataset-level summaries to the terminal.
Use a fresh output directory for each experiment.
Add `--skip_decompress --skip_eval` for encoding only, or `--skip_compress` to
decode and evaluate existing streams using the same paths and weights.
Individual files can also be processed with `encode.py`, `decode.py`, and
`evaluate.py`; run each program with `--help` for its available arguments.

Before a full run, check one frame using the same pipeline:

```bash
CUDA_VISIBLE_DEVICES=0 python run_rd_pipeline.py \
    --dataset_mode FORD --ckpt='./LiACM_Pro_FORD.pt' \
    --input_glob='/path/to/Ford/Ford_02_q_1mm/Ford_02_q_1mm/Ford_02_vox1mm-0100.ply' \
    --eval_input_glob='/path/to/Ford/Ford_02_q_1mm/Ford_02_q_1mm/Ford_02_vox1mm-0100.ply' \
    --depth_offsets=0 \
    --compressed_path='./my_test/smoke/compressed' \
    --decompressed_path='./my_test/smoke/decompressed' \
    --output_csv='./my_test/smoke/metrics.csv' \
    --resolution=30000 --input_norm=none --enable_cd --cd_mode=gaem
```

D1/D2-PSNR use the symmetric metric output. The peak is 30,000 mm for Ford and
59.7 m for SemanticKITTI. `cd_mm` reports the maximum of the two directional mean
nearest-neighbor Euclidean distances, converted to mm for both datasets; it is
not squared CD. Check that every CSV row has `status=ok` and no `error`.
Printed GPU memory is PyTorch peak allocated memory in MiB (the legacy log label
says MB), not total device memory or training memory.
